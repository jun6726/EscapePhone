# 플레이테스트 분석 가이드

## 수집 단위

각 퍼즐은 `elapsedMs`, `sessionCount`, `wrongAttemptCount`, `wrongReasonCounts`, `hintViewCount`, `exitEvents`를 기록한다. 엔딩에서는 난이도 1~5와 최대 1,000자의 자유 의견을 받는다. 계정이나 광고 식별자는 기록하지 않는다.

`appBackgroundOrClosed`는 모바일 운영체제 특성상 단순 백그라운드 이동과 앱 종료를 완전히 구분할 수 없으므로 하나의 이탈 유형으로 집계한다. `backNavigation`은 게임 안에서 뒤로 이동한 경우다.

## 개선 우선순위

| 관찰 결과 | 해석 | 권장 개선 |
|---|---|---|
| 소요 시간과 오답이 모두 높음 | 규칙 또는 단서가 불명확함 | 문제 설명과 1단계 힌트를 구체화 |
| 소요 시간은 높고 오답은 낮음 | 읽기·조작·탐색이 느림 | 정보량 축소, 버튼·대상 가시성 개선 |
| 특정 오답 원인이 집중됨 | 하나의 규칙을 반복 오해함 | 해당 규칙 주변에 즉시 피드백 추가 |
| 힌트 조회 직후 성공률이 높음 | 힌트는 유효하지만 기본 단서가 약함 | 1단계 힌트 일부를 기본 UI로 승격 |
| 같은 퍼즐에서 세션·이탈이 반복됨 | 피로, 막힘 또는 중단 지점임 | 저장 복귀 안내, 난이도 완화, 조작 개선 |
| 체감 난이도 4~5와 이탈이 함께 높음 | 실제 난이도 문제 가능성이 큼 | 우선 수정 대상으로 지정 |
| 체감 난이도 1~2인데 완료 시간이 짧음 | 너무 쉬울 가능성이 있음 | 방해 선택지나 추론 단계를 소폭 강화 |

최소 10~20개 보고서를 모은 뒤 중앙값을 기준으로 비교한다. 극단적으로 긴 단일 기록보다 동일 퍼즐에서 반복되는 오답 원인과 이탈 패턴을 우선한다.

## 보고서 회수

동의한 사용자의 JSON은 로컬 재시도 큐를 통해 설정된 HTTPS 수집 서버로 비동기 전송한다. 서버가 설정되지 않은 개발 빌드에서는 엔딩의 **익명 분석 보고서 공유** 버튼으로 현재 세션을 직접 전달할 수 있다. 운영 전 개인정보 처리방침, 삭제·보존 정책과 수집 API 검증을 확정한다. 자세한 서버 계약은 `ANALYTICS_BACKEND_KO.md`를 참고한다.
